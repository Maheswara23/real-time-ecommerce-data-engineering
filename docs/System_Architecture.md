# System Architecture

## 1. Overview

The Real-Time E-Commerce Data Engineering & Analytics Platform is designed to ingest, process, transform, and analyze streaming business events generated by an e-commerce application.

The platform follows the Medallion Architecture (Bronze, Silver, and Gold) using Databricks and Delta Lake to ensure scalable, reliable, and maintainable data pipelines.

Apache Kafka serves as the streaming platform for event ingestion, while MySQL and MongoDB store structured and semi-structured business data respectively. Power BI consumes curated Gold-layer datasets to provide interactive dashboards for business users.

# 4. Architecture Components

## 4.1 Apache Kafka

Kafka acts as the real-time messaging system responsible for receiving business events from different services.

Kafka Topics include:

- orders_topic
- payments_topic
- inventory_topic
- shipping_topic
- customers_topic
- reviews_topic
- clickstream_topic

---

## 4.2 Databricks

Databricks consumes streaming events from Kafka using Structured Streaming.

Responsibilities include:

- Reading Kafka streams
- Parsing JSON events
- Data validation
- Data transformation
- Writing Delta tables
- Aggregating business metrics

---

## 4.3 Delta Lake

Delta Lake stores data in three logical layers:

### Bronze

Raw immutable streaming events.

### Silver

Validated, cleaned, and enriched datasets.

### Gold

Business-ready analytical datasets optimized for reporting.

---

## 4.4 MySQL

Stores structured business entities including:

- Customers
- Products
- Orders
- Payments
- Inventory
- Shipping
- Suppliers

---

## 4.5 MongoDB

Stores flexible document-based data including:

- Product Reviews
- Customer Support Chats
- Clickstream Events
- User Sessions

---

## 4.6 Power BI

Power BI connects to Gold-layer datasets to create dashboards for:

- Executive Summary
- Sales Analytics
- Customer Analytics
- Inventory Monitoring
- Shipping Performance
- Product Performance

---

# 5. End-to-End Data Flow

The platform follows the following workflow:

1. Business events are generated by the e-commerce application.
2. Events are published to Apache Kafka topics.
3. Databricks consumes streaming data.
4. Raw data is stored in Bronze Delta tables.
5. Bronze data is cleaned and transformed into Silver tables.
6. Silver tables are aggregated into Gold tables.
7. Structured data is stored in MySQL.
8. Semi-structured data is stored in MongoDB.
9. Power BI reads Gold tables to generate dashboards.

---

# 6. Medallion Architecture

## Bronze Layer

Purpose:

- Store raw Kafka events
- Preserve original data
- Support replay and debugging

Examples:

- bronze_orders
- bronze_payments
- bronze_inventory

---

## Silver Layer

Purpose:

- Remove duplicates
- Handle missing values
- Validate business rules
- Standardize formats
- Join reference data

Examples:

- silver_orders
- silver_customers
- silver_inventory

---

## Gold Layer

Purpose:

- Business KPIs
- Aggregated metrics
- Dashboard-ready tables

Examples:

- gold_sales_summary
- gold_customer_metrics
- gold_inventory_status
- gold_product_performance
